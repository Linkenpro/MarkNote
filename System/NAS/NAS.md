# NAS 远程访问

飞牛 OS 使用 Lucky 管理 IPv6 DDNS 与反向代理。以下保留原部署参数，未记录的配置列为待补。

## 网络环境

IPv6 直连需要 NAS 获得可从公网路由的 IPv6 地址、访问端具备 IPv6 连通性，并放行沿途防火墙及目标端口。DDNS 将域名更新到当前地址，反向代理将请求转发到对应服务。

光猫未桥接不等于 IPv4 一定无法访问；还取决于公网 IPv4、NAT 和端口映射。IPv6 也不会自动绕过防火墙。

## Lucky 部署

| 配置项 | 原记录 |
| --- | --- |
| 系统 | 飞牛 OS |
| 镜像 | `gdy666/lucky`，部署前确认所用版本 |
| 网络模式 | Host，共享宿主机网络 |
| 宿主机目录 | `/vol1/1000/docker/lucky` |
| 容器配置目录 | `/goodluck` |
| 参考网卡 | `eno1`，以实际网卡为准 |
| 局域网管理地址 | `http://192.168.10.254:16601` |

Host 模式无需额外端口映射。确认挂载方向为宿主机目录 → `/goodluck`，以便持久化配置。

原记录中的初始账号密码均为 `666`，仅作为旧版记录；以所用版本说明为准，首次登录后修改，管理入口保留在可信网络内。

## 域名与访问配置

待补充实际配置，不代表已经部署完成：

- DDNS：域名、AAAA 记录、地址来源网卡、更新周期。
- 反向代理：入口域名与端口、后端 NAS 服务地址。
- HTTPS：证书申请方式、证书保存位置、续期方式。
- 防火墙：光猫、路由器与 NAS 上实际放行的业务端口。

DNS 基础见 [Cloudflare](../Cloudflare/Cloudflare.md)。凭据保存在服务配置中，笔记仅保留占位符。

## 排查顺序

1. 在局域网确认 Lucky 和后端服务可访问。
2. 确认 NAS 的公网 IPv6 与域名 AAAA 记录一致。
3. 检查 IPv6 防火墙及服务监听地址、端口。
4. 从具备 IPv6 的外部网络测试域名与 HTTPS。
